```
合奏：我方場上同時有三位「不同的」騷靈角色時，效果啟動。
```

**合奏是動態光環**，不是一次性加成 —— 湊齊瞬間三隻同時變 3/5，任何一位陣亡，另外兩位的加成立刻消失。
這讓對手有明確的破解點（殺掉最脆的那一隻），而不是「湊齊就無敵」。

三張卡是**中立**的，任何英雄都能嘗試合奏；騷靈三姊妹英雄的優勢在於能用探尋穩定湊齊。

### 人妖組：官方四組（✅ 已實作）

**用原作永夜抄的四組自機組，不是 BOSS 側的配對。**
（本文件先前把妹紅＋慧音那組寫成「自機組」是錯的，那是 BOSS 配對。）

| 組名 | 搭檔 | 湊齊時 |
|---|---|---|
| 幻想結界組 | 博麗靈夢 ＆ 八雲紫 | 兩者 +1/+1；紫再加：你的回合開始時抽 1 張 |
| 禁咒詠唱組 | 霧雨魔理沙 ＆ 愛麗絲 | 愛麗絲 +1/+1；魔理沙：你每發動一張符卡就 +1/+0 |
| 夢幻紅魔組 | 十六夜咲夜 ＆ 蕾米莉亞 | 兩者 +2/+1 |
| 幽冥住人組 | 魂魄妖夢 ＆ 西行寺幽幽子 | 兩者 +1/+1；妖夢再加：回合結束時對敵方英雄 2 傷 |

加成掛在**既有的八張中立角色卡**上，沒有另做專屬版本 ——
那會讓卡池多出八張重複角色，而且掛在中立卡上任何牌組都能組，
組牌時要不要投入 9～11 費去湊一組才成為真正的取捨。

引擎只需要一個 `pair` 欄位與 `paired(s, u)`：

```js
function paired(s, u) {
  if (!u || u.silenced) return false;          // 封印＝卡面全部失效，搭檔關係也斷
  var partner = def(u.defId).pair;
  if (!partner) return false;
  return unitsOf(s, u.owner).some(function (x) {
    return x !== u && x.defId === partner && !x.silenced;
  });
}
```

不用族群判定 —— 否則會變成「隨便一個人類配一個妖怪都算」，
而原作的四組是固定的四對人，寫死才對得上。

---|---|
| 藤原妹紅 ＋ 上白澤慧音 | 兩者 +1/+1 並獲得森羅結界 |
| 八意永琳 ＋ 蓬萊山輝夜 | 你的回合開始時抽 1 張 |
| 因幡帝 ＋ 鈴仙 | 兩者獲得隱行 |
| 莉格露 ＋ 米斯蒂婭 | 兩者獲得奇襲 |

照原作的自機組配對，玩家一看就懂，不需要記族群規則。

## 6. 角色卡的設計原則（已定案）

**角色卡只能是三種來源：**

1. **原作有的具名角色**（蕾米莉亞、芙蘭朵露、琪露諾…）
2. **原作有的雜魚**（各種妖精、幽靈、亡靈、蝙蝠、蟲…）
3. **其他原作沒提到的，盡可能不加入**

推論出來的三條規則：

- `「」` 的命名格式**只給符卡、結界與 BGM**。角色卡用實體名稱。
- **不做「英雄本人的第二張卡」**。蕾米已經有角色卡，就不需要再有一張「Scarlet Devil」；
  組蕾米的人本來就會放芙蘭朵露當大身材。
- **職稱不能當成另一個角色**。「紅魔館的女僕長」就是咲夜、「白玉樓的門番」就是妖夢。

> 不用擔心角色不夠 —— 組牌時本來就會混入其他角色，不會只放英雄自己那幾張。

## 7. 裝備系統（留給虹龍洞包）

魔理沙的迷你八卦爐、魔法使的帽子、魔導書**已先改成結界**（階段 3b）——
它們是道具不是生物，但真正的裝備需要新卡種與新區域，
所以留到虹龍洞（TH18，原作就是卡牌／能力卡系統）一起做，屆時這三張改掛裝備。

已定案的設計方向：

| 項目 | 決定 |
|---|---|
| 裝在哪 | **英雄身上**（不是角色身上）|
| 專屬裝備 | 每位英雄有一件代表裝備（魔理沙＝八卦爐）。**別人也能裝，但裝自己的專屬不用花靈力** |
| 耐久度 | 觸發時或角色攻擊時 -1，歸零消失。與永續的結界做出區隔 |
| 幾件 | 平時 1 件；**虹龍洞包會出一張專屬場地，讓英雄可以同時裝多件** |

「專屬免費」這條很關鍵 —— 它讓「英雄代表裝備」不只是風味，而是真正的組牌誘因：
放自己的專屬裝備等於白賺一個回合的節奏，放別人的則要付出代價。

### 引擎的小改動

`onAllySpell` 追加第三個參數：剛剛發動的那張符卡的定義。
沒有這個參數就寫不出「你發動**帕秋莉的**符卡時」這種條件。舊卡不受影響。
